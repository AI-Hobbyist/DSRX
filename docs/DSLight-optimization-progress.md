# DSLight 优化目标与进度

日期：2026-11-12。用户已授权实现五个优先方向。范围限定 DSLight，保留原架构 checkpoint、训练与受支持部署行为；新容量配置需独立训练，量化质量需授权校准/评估数据。

按以下顺序完成，每个阶段自动验证通过后检查差异、单独提交并推送，再进入下一阶段：

1. 条件投影跨采样步缓存。原生 eager Reflow/DDPM 已接入局部预计算，五项骨干回归通过（数值、参数预算、trace、乐句隔离、RK2 每次采样仅投影一次）。训练和既有导出入口保留普通条件路径；trace 后不保留准备接口的模块仍走普通路径。进入独立提交/推送检查点。
2. 时间编码频率预存与逐元素融合已实现：FP32 非持久化频率缓存随设备转换重建，低精度保留原有计算顺序；eval 调制使用 addcmul，训练表达保持原样。七项回归通过，包括精度往返和训练/eval 等价性。门控后的大投影不拆成两次卷积，避免增加算子；尚未宣称实测提速。进入独立提交/推送检查点。
3. 通道宽度优化。未开始。复用已有容量档，完善可复跑的同条件容量/延迟/质量对比；不把缩窄配置冒充旧权重无损优化。
4. 辅助输出、浅起点与实际 NFE 的少步质量定位。未开始。区分前级误差与修正效果，并支持真实数据评估。
5. 选择性量化。未开始。优先大 pointwise/投影矩阵，保留关键浮点路径；验证体积、误差、运行时和部署契约。

当前实际仓库为 DSRX/，分支 ds_light_backend，上游 origin/ds_light_backend。外层工作区另有一个尚无提交的仓库，不能将所有外层未跟踪资料一并提交。

用户已提供 ckpt/dslight/model_ckpt_steps_100000.ckpt 及配置和配套声码器。配置为 160 通道、10 层、224 维条件的 Reflow，默认 20 步。已确认 data/opencpop 有 wavs/ 和包含音素/时长/音符的 transcriptions.csv；配置引用的 data/pre/binary/all_in_one_dslight 尚不存在，需沿现有数据链准备评估特征，不重新标注。真实歌声/听音未执行时记录 MANUAL/PENDING，继续可自主完成的实现与自动验证，不将其记为 PASS 或因此标记 blocked。

所有构建和测试以前台 PowerShell Tee-Object 保存日志、立即检查退出码。模型原始大小、真实质量与速度分别记录，不从参考 SVF 样本推断本项目性能。
